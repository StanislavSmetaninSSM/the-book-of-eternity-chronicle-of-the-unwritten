# Сохранения и изображения

Как устроено хранение сгенерированных картинок и как переносится сохранение между браузерами.

## Где что лежит

| Данные | Место | Ключ |
| --- | --- | --- |
| Состояние игры, история, журналы | IndexedDB `gemini-rpg-db`, сторы `autosaves`, `save_slots`, `interrupted_turns` | `current_autosave`, `last_known_good_save`, `slotId`, `pending-turn` |
| Метаданные слотов, метка автозаписи | `localStorage` | небольшие строки, без картинок |
| Байты изображений | IndexedDB `gemini-rpg-images`, стор `images` | `id = sha256(байты)` |

В сохранении `gameState.imageCache` хранит не base64, а ссылку `blob:<sha256>`. В памяти, после загрузки, `src` снова `data:`-URL — на этом держится весь UI (`ImageRenderer`, галерея, профиль, модалки) и он об изменениях не знает.

Адресация контентная: одинаковые картинки в разных слотах, crash-recovery и pre-turn чекпоинтах хранятся один раз.

## Запись и чтение

- `utils/saveImageRefs.ts` — `dehydrateImageCache` / `hydrateImageCache`: data URL ⇄ ссылка. `dehydrate*` вызывают `saveToDB`, `saveToDBSlot`, `saveCrashRecoveryPoint`, `saveInterruptedTurnRecovery`; `hydrate*` — соответствующие загрузки.
- `utils/imageBlobStore.ts` — само хранилище: `storeImageDataUrl`, `readImageDataUrl`, `sweepUnreferencedImages`.
- Ошибка записи картинки не превращается в «мёртвую» ссылку: payload остаётся inline, а сохранение дальше живёт по обычному пути (при нехватке квоты `stripImagesForQuota` сбрасывает кеш и сообщает об этом игроку).

## Уборка

`sweepUnusedImages` в `utils/fileManager.ts` собирает ссылки из всех сохранений (`autosaves`, `save_slots`, `interrupted_turns`) и удаляет из хранилища всё, на что ссылок нет.

- рутинная уборка идёт после автозаписи и записи слота и ограничена одним запуском в 3 минуты, потому что читает все сохранения;
- удаление слота и миграция запускают принудительную уборку;
- свежезаписанные байты защищены 60-секундным grace-периодом;
- если картинка не находится при загрузке, запись выкидывается из кеша, а `missingImageCount` сообщает, сколько потеряно (поле живёт только в памяти).

## Перенос между браузерами

Экспорт предлагает два вида:

1. один файл `gemini-rpg-save-<дата>.json` — картинки внутри base64, ничего не нужно сопоставлять;
2. пара `…-save.json` (ссылки `blob:`) + `…-images.json` (`format: "book-of-eternity-image-bundle"`, карта ссылка → data URL).

Импорт (`utils/saveBundle.ts`) принимает любое количество документов: сохранение, оба файла или только картинки; порядок не важен. Если ключ в файле картинок не совпадает с содержимым, сохранение переписывается по алиасам вместо потери картинки. Сохранение без файла картинок открывается, если байты уже есть в этом браузере.

## Миграция старых сохранений

`migrateInlineImagesToImageStore()` один раз при старте выносит base64 из автозаписи, crash-recovery, всех слотов и pending-чекпоинта. Перед записью запись перечитывается и сверяется по `timestamp`/`createdAt`, поэтому сохранение, сделанное во время миграции, не перезаписывается; повторный запуск ничего не делает.
