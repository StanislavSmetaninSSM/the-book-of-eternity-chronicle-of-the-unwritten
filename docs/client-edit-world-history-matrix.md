# Матрица player actions: мир, история и хранилища

Аудит этапа 1, **не список разрешённых клиентских команд**. `useGameLogic` передаёт весь `createPlayerActionsManager` через `guardGameplayActions`; сейчас host/none допускаются, player/spectator блокируются, включая сортировку, несмотря на её презентационное назначение. Будущие права не установлены: «свой» означает проверенную хостом связь соединения и единственного playerId, а не доверие полям клиента. Переходы ролей, restore и turn требуют проверки непосредственно перед применением. Для любой сетевой команды нужны session/base revision, operation ID, atomic commit, dedupe, ACK/unknown и разрешение конфликта; таблица не доказывает их наличие.

Маршруты ниже описывают известные передачи из `App.tsx`, а не исчерпывают все возможные пути вызова. Многие поля сохраняются и входят в контекст ГМ; изменение ref внутри React updater не является commit. Разрешение `allowHistoryManipulation` есть только там, где его реально проверяет менеджер; UI-проверка сама по себе не авторизация. Для удаления требуется согласованная политика подтверждения и stale-base отказ, особенно при индексах/диапазонах. Legacy или повторные ID нельзя разрешать угадыванием.

| Entry point | UI / цель, фактическая запись | Предполагаемые проверки, конфликты и последствия |
| --- | --- | --- |
| `spendAttributePoint` | App → CharacterSheet; персонаж и характеристики, пересчёт derived stats, context. | Свой playerId, допустимый ключ, очки и предел 100 на актуальной базе; двойная трата необратима без явного отката. |
| `setAutoCombatSkill` | App → CharacterSheet / CombatTracker; player autoCombatSkill и context. | Свой playerId, существующий навык/допустимый null, конфликт с удалением/сменой навыка. |
| `editChatMessage` | App → SidePanel; history по индексу и context responseHistory, с allowHistoryManipulation. | Устойчивая идентичность сообщения или CAS содержимого/позиции; stale index может перезаписать другое сообщение. История ГМ изменяется. |
| `editNpcData` | App → SidePanel / CombatTracker / CharacterSheet; NPC поле и context, history setting. | NPCId, права и whitelist полей/типов; не допускать смену ID или полную подмену связей. Повторный ID и concurrent edit — конфликт. |
| `editQuestData` | App → SidePanel; active/completed quests и context, history setting. | questId уникален в обеих коллекциях, разрешённые поля и статус; конфликты завершения, связанных целей и ссылок. |
| `editItemData` | App → SidePanel; player inventory и context, history setting. | Свой playerId/itemId, whitelist и проверка стека, слотов, производных значений; дубли и смена ID опасны. |
| `editFactionData` | App → SidePanel; faction и context, history setting. | factionId, права и валидные поля; проекты, отношения и связанные ссылки могут устареть. |
| `editLocationData` | App → SidePanel / LocationLog; visitedLocations и при совпадении currentLocation, context, history setting. | locationId и допустимые поля; worldMap отдельно не обновляется, требуется согласование копий/связей, конфликт при смене локации. |
| `editPlayerData` | App → SidePanel / CharacterSheet; произвольное поле playerCharacter и context, history setting. | Свой playerId, whitelist/валидация и пересчёт; не принимать произвольный player объект/ID/слоты как команду. |
| `editWorldState` | App → SidePanel → WorldPanel; календарные минуты/date/day и context worldState, history setting. | Права на мир, валидный календарь и диапазоны; конфликт с продвижением времени/сменой календаря, может менять последствия мира. |
| `editWeather` | App → SidePanel / WorldPanel; worldState.weather и context, history setting. | Права на мир, проверка значения/базы и конфликта с ходом. |
| `editWorldStateFlagData` | App → SidePanel / WorldPanel; flags и context, history setting. | Уникальный flagId, whitelist и права; смена ID/связей или конкурентное удаление — конфликт. |
| `onEditNpcMemory` | App → SidePanel / CharacterSheet; NPC unlockedMemories и context, history setting. | NPCId + memoryId, права, актуальная версия и допустимые поля; текущая замена целиком может затереть concurrent edit. |
| `onDeleteNpcMemory` | App → SidePanel / CharacterSheet; фильтр NPC memories и context, history setting. | NPCId + уникальный memoryId, права/CAS; необратимая потеря знания, дубли удаляются вместе. |
| `deleteMessage` | App → история чата; `setUserGameHistory`, отдельный утилитарный путь. | ID сообщения или CAS и политика прав; index после вставки может выбрать другое. Необратимая история. |
| `clearHalfHistory` | App → история; `setUserGameHistory`, утилита. | Явное подтверждение и точный snapshot/граница, без применения к изменившейся истории; необратимо. |
| `deleteLogs` | App → очистка логов; gameLog и combatLog, host history hold. | Отдельная политика на журналы/представление, snapshot/CAS и подтверждение; не смешивать с responseHistory. |
| `forgetNpc` | App → SidePanel / NpcLog; helper меняет gameState. | NPCId, права, точные затронутые связи и подтверждение; конфликт с появлением новых данных NPC, эффект необратим. |
| `forgetFaction` | App → SidePanel; helper меняет gameState. | factionId, права и ссылки/проекты; проверять точную семантику helper, необратимо. |
| `clearNpcJournal` | App → DetailRenderer; NPC journalEntries и context, history setting. | NPCId, snapshot журнала и подтверждение; новые записи между запросом и commit не удалять молча. |
| `deleteNpcJournalEntry` | App → DetailRenderer; удаление записи по индексу и context, history setting. | NPCId + ID записи или CAS; сдвиг индекса и повтор — конфликт, удаление необратимо. |
| `deleteOldestNpcJournalEntries` | App → DetailRenderer; удаление числа старых записей и context, history setting. | NPCId, валидное count и точный диапазон/версия; новая или переупорядоченная история — конфликт. |
| `forgetLocation` | App → SidePanel / LocationLog; visited и worldMap с удалением adjacency links, context, history setting. | locationId, ссылки и зависимые current/visited/map копии; неоднозначные legacy links не угадывать; каскад необратим. |
| `forgetQuest` | App → SidePanel / QuestLog; фильтрация active/completed, context, history setting. | questId уникален, актуальный статус и подтверждение; дубли или завершение после запроса — конфликт. |
| `deleteCustomState` | App → SidePanel / CharacterSheet; playerCustomStates и context, history setting. | Итоговый export hook переопределяет менеджер: проверять его отдельно. Свой playerId + уникальный stateId, не имя; конфликт/необратимость. |
| `deleteNpcCustomState` | App → SidePanel / DetailRenderer; NPC customStates и context, history setting. | NPCId + stateId; текущий fallback по имени может удалить несколько записей; права и связанные эффекты требуют решения. |
| `deleteWorldStateFlag` | App → SidePanel / WorldPanel; flags и context, history setting. | Уникальный flagId, права, версия/зависимости; удаление повторных ID и необратимость. |
| `deleteWorldEvent` | App → SidePanel / WorldPanel; worldEventsLog и context, history setting. | Уникальный eventId, точная версия и подтверждение; потеря исторического контекста необратима. |
| `deleteWorldEventsByTurnRange` | App → SidePanel / WorldPanel; фильтр worldEventsLog по turnNumber и context, history setting. | Границы, точный набор eventId или CAS всей базы; новые события в диапазоне не должны исчезать после задержки. |
| `onRegenerateId` | App → SidePanel / CharacterSheet; item/NPC/quest либо location, несколько setters/context, history setting. | Не выдавать сетью произвольный entity/type: нужна атомарная миграция всех ссылок, единственная цель и отсутствие коллизий. Location меняет ref worldMap без полного обновления ссылок; legacy fallback по имени неоднозначен. |
| `updateNpcSortOrder` | App → SidePanel → NpcLog; npcSortOrder в gameState, не context. | Презентация, но хранится в общем snapshot и блокируется сейчас; отдельно решить local persistence/rebase. |
| `updateItemSortOrder` | App → InventoryScreen / SidePanel; player itemSortOrder, manual criteria и context. | Презентация в сохраняемом персонаже; local preference или авторитетное поле пока не решены, конфликт с удалением itemId. |
| `updateItemSortSettings` | App → InventoryScreen / SidePanel; player criteria/direction и context. | Презентация в общем персонаже; валидные значения и политика local preference, сейчас блокируется. |
| `updateNpcItemSortOrder` | App → InventoryScreen / CharacterSheet; NPC order/manual criteria и context. | NPCId, допустимый порядок; презентационное поле общего NPC, разрешения и local persistence не определены. |
| `updateNpcItemSortSettings` | App → InventoryScreen / CharacterSheet; NPC criteria/direction и context. | NPCId и валидные значения; локальное предпочтение против общей записи требует решения. |
| `updateActiveSkillSortOrder` | App → CharacterSheet → SkillsView; player order и context, history setting. | Свой playerId/существующие навыки; порядок презентационный, но хранится в общем snapshot и сейчас заблокирован. |
| `updatePassiveSkillSortOrder` | App → CharacterSheet → SkillsView; player order и context, history setting. | Аналогично active: устаревшие имена навыков, версия списка и политика локального хранения. |
| `clearNpcJournalsNow` | App → SidePanel → GameMenuView; journals всех NPC и context, history setting. | Права на весь мир, подтверждение и CAS набора/содержимого; новые журналы не удалять молча. Необратимо. |
| `clearAllCompletedFactionProjects` | App → SidePanel → FactionDetailsRenderer; faction completedProjects и context, history setting. | factionId, права и точный набор завершённых проектов; concurrent completion не должен исчезнуть. Необратимо. |
| `clearAllCompletedNpcActivities` | App → CharacterSheet; NPC completedActivities и context, history setting. | NPCId, права и точный набор завершённых записей; concurrent completion не должен исчезнуть. Необратимо. |
| `placeAsStorage` | App → SidePanel → ItemDetailsRenderer; inventory/equipped и currentLocation storage, context. | Свой playerId + itemId/locationId, тип и полный состав контейнера, уникальность, стабильный storageId; конверсия metadata и ссылки пока не доказаны. |
| `moveToLocationStorage` | App → StorageScreen; inventory и storage contents, context. | playerId/locationId/storageId/itemId, доступ и положительное целое; count/ID проверяются локально, но имя-слияние, contentsPath, экипировка и права остаются риском. |
| `retrieveFromLocationStorage` | App → StorageScreen; storage contents и inventory, context. | Аналогично, плюс вес/лимиты; локально часть ошибок quantity/ID отвергается, но metadata и слияние по имени небезопасны. |
| `shareStorageAccess` | App → StorageScreen передаёт prop; в текущем StorageScreen кнопки для него нет. Записывает owner type/authorizedUsers и context. | locationId/storageId, текущий владелец, однозначный targetPlayerId и согласие/права; duplicate IDs и concurrent revoke. |
| `revokeStorageAccess` | App → StorageScreen передаёт prop; кнопки нет. Записывает authorizedUsers/owner type и context. | Только проверенный владелец, уникальные storage/player IDs, конфликт с передачей предметов и предыдущим share. |

Проверка `scripts/client-world-history-matrix.test.mjs` сверяет экспортируемые имена с отдельными строками и несколько реальных соединений UI/guard. Она не проверяет семантику, полноту UI, сериализацию или права. Подробности других публичных hook/сетевых путей, обновлений настроек, ран и инвентаря остаются в [общем аудите](client-edit-operation-audit.md) и [матрице инвентаря](client-edit-inventory-matrix.md).
